# Reproducibility bundle

Code, data and outputs for *Selecting energy-management policies for a grid-limited residential microgrid with coupling-aware multi-period hesitant fuzzy decision analysis*.

Every number, table and figure in the paper and in the Supplementary Material is produced by `run_all.py` from the two data files in `data/`, with fixed random seeds (`SEED = 2026`).

## Quick start

The bundle needs Python 3.10 or newer and the packages in `requirements.txt`. Install them **before** the first run; otherwise `run_all.py` stops and lists the missing packages.

**Windows (Command Prompt or PowerShell), from the bundle folder:**

```bat
py -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python run_all.py --skip-gsa
```

**Linux or macOS:**

```bash
python3 -m venv .venv && source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python run_all.py --skip-gsa
```

Run options:

```bash
python run_all.py --skip-gsa     # everything except the Morris runs (reuses results/gsa_morris.csv)
python run_all.py                # full run, including the 120 Morris simulations
python run_all.py --figures-only # redraw figures from results/
```

Runtime (2 CPU cores): about 6–7 min for `--skip-gsa`, plus about 15 min for the Morris screening (120 re-tuned simulations). The Morris runs are resumable: progress is written to `results/gsa_morris.partial.csv` and an interrupted run continues from there. No network access is needed at run time.

**Troubleshooting.** `ModuleNotFoundError: No module named 'pvlib'` (or another package) means the requirements were not installed into the Python that runs the script. Activate the virtual environment (`.venv\Scripts\activate` on Windows) and run `python -m pip install -r requirements.txt` again; using `python -m pip` guarantees that the packages go to the same interpreter. If PowerShell refuses to run the activation script, use `.venv\Scripts\python.exe -m pip install -r requirements.txt` and `.venv\Scripts\python.exe run_all.py --skip-gsa` instead.

`ImportError: DLL load failed while importing h5: An Application Control policy has blocked this file` comes from h5py, an optional dependency of pvlib that Windows (Smart App Control or a managed security policy) refuses to load. The bundle does not use h5py: `src/ems_data.py` detects this case and loads pvlib without it, and the results are unchanged (checked by a full run with h5py blocked, which reproduced every results file, table and figure byte for byte). If Windows blocks another compiled package in the same way (for example numpy, scipy or matplotlib), the policy has to be relaxed for the Python installation, or the bundle run in a Python that the policy allows, such as Anaconda or Windows Subsystem for Linux.

## Data provenance

| File | Content | Source | MD5 |
|---|---|---|---|
| `data/zurich_electricity_consumption.csv` | 15-min metered low-voltage demand (ewz, Value_NE5) and weather (UGZ station Zch_Stampfenbachstrasse: global horizontal irradiance, air temperature, wind speed), 2015–2022 | City of Zurich open government data, as distributed with the darts library (`datasets/zurich_electricity_consumption.csv` at https://github.com/unit8co/darts) | `764bdd3bb4f9066ba7523accf9089505` |
| `data/household_load_15min.csv` | Stochastic load of 14 apartments, 2015–2021 | Generated by `src/gen_household_load.py` (richardsonpy, Richardson et al. 2010), driven by the Zurich irradiance; one seed per household-year | `169a096911134837c708042cbe266b1c` (richardsonpy 0.2.3) |

`src/ems_data.py` checks the MD5 of the Zurich file before use. It corrects the 30-min early stamping of the hourly weather means and converts all times to local standard time (CET). The BDEW H0 comparator profile is generated at run time with demandlib. To regenerate the household load from scratch, run `python src/gen_household_load.py`. The file is cached, so `run_all.py` does not regenerate it.

## Analysis design

* **Policies.** A1 renewable-first, A2 battery, A3 price-elastic demand response, A4 hybrid (`src/ems_model.py`, `simulate`). Perfect-foresight daily LP ceilings L2 (battery), L3 (DR) and L4 (both) are solved with HiGHS through SciPy (`lp_benchmark`).
* **Out-of-sample protocol.** The grid-charging target of A2/A4 is tuned on 2015–2017 (`src/pipeline.py`, `tune`), and all decision results use 2018–2021 (1,460 days). Every simulation-based sensitivity run re-tunes.
* **Criteria.** C1–C5 are computed per day and tariff period with reference-point normalization (`block_criteria`). Storage provenance is tracked with a well-mixed two-pool battery.
* **Dynamic hesitant fuzzy soft set.** Period-level HFEs with context-dependent active criteria; the baseline activates every criterion in every period, and `section_context` in `run_all.py` evaluates self-consumption switched off off-peak and on-peak.
* **Decision analysis.** `src/mcdm.py` contains the HFE constructions; the independent, comonotone and empirical couplings with AR/EIN/ALG means and ε-capping; risk-averse scores and lower-tail means; MABAC, WSM, TOPSIS and HF-TOPSIS; SMAA; and the moving-block bootstrap.
* **Global sensitivity.** Morris screening over five factors with SALib (`src/gsa.py`).

## Verifying the results

To check that the bundle reproduces the paper, move `results/` and `figures/` aside, run `python run_all.py` (or `--skip-gsa` with `results/gsa_morris.csv` restored), and compare the new `results/*.csv`, `results/summary.json` and `results/tables/*.tex` with the originals. A from-scratch `--skip-gsa` run on Python 3.13 with the newest package set listed in `requirements.txt` reproduced every CSV file, `summary.json` and every table file byte for byte. With the older package set, every number used in the paper and every table file was identical; only the bootstrap confidence intervals of the Morris indices (`mu_star_conf` in `results/gsa_indices.csv`, not reported in the paper) differ, because SALib changed its resampling between versions. On Windows, CSV files are written with Windows line endings, so compare them by content rather than byte for byte.
